# 达尔文.skill (Darwin Skill)

**GitHub**: [alchaincyf/darwin-skill](https://github.com/alchaincyf/darwin-skill)  
**作者**: 花叔 (Alchain)  
**灵感来源**: Andrej Karpathy 的 [autoresearch](https://github.com/karpathy/autoresearch)  
**定位**: 让 Skill 持续进化的评估→改进→测试→保留/回滚系统

---

## 📋 核心理念

> **女娲造 Skill，达尔文让 Skill 进化。**
>
> **只保留改进，时间就站在你这边。**

### 问题背景
- 当有 10 个 Skills 时可以手动维护
- 当有 60+ 个 Skills 时，需要系统化进化机制
- 传统 Skill 审查是**纯结构性**的（格式对不对），但格式完美的 Skill 效果可能很差

### 核心创新
**达尔文.skill 同时评估结构质量和实际效果，然后只保留真正有改进的修改。**

## 🏗️ 核心机制

### 与 Karpathy autoresearch 的映射

| autoresearch | 达尔文.skill | 为什么这样映射 |
|-------------|-------------|---------------|
| `program.md` | 本 `SKILL.md` | 定义评估标准和约束规则 |
| `train.py` | 每个待优化的 `SKILL.md` | 被优化的资产，每次实验只改它 |
| `val_bpb` | 8 维加权总分（满分 100） | 可量化的优化目标 |
| `git ratchet` | keep / revert 机制 | 只保留有改进的 commit |
| `test set` | `test-prompts.json` | 验证改进是否真的有效 |
| 全自主运行 | **人在回路** | Skill 的好坏比 loss 更微妙，需要人的判断 |

## 📐 设计原则

| 原则 | 说明 |
|------|------|
| **01 单一可编辑资产** | 每次只改一个 SKILL.md，变量可控，改进可归因 |
| **02 双重评估** | 结构评分（静态分析）+ 效果验证（跑测试看输出） |
| **03 棘轮机制** | 只保留改进，自动回滚退步，分数只升不降 |
| **04 独立评分** | 评分用子 agent，避免「自己改自己评」的偏差 |
| **05 人在回路** | 每个 Skill 优化完后暂停，用户确认再继续下一个 |

## 📊 评分体系（满分 100）

### 结构维度（60 分）— 静态分析
- 格式规范性
- 步骤完整性
- 路径可访问性
- ...

### 效果维度（40 分）— 实测表现
- **实测表现权重最高（25 分）**
- Skill 写得再漂亮，跑出来效果不好就是零
- 必须实际运行测试用例验证

## 🔄 进化流程

### Phase 2 核心逻辑

```
1. 找出得分最低的维度
       ↓
2. 针对该维度生成 1 个具体改进方案
       ↓
3. 编辑 SKILL.md，git commit
       ↓
4. 子 agent 独立重新评分
       ↓
5. 新分 > 旧分 → 保留；否则 → git revert
       ↓
6. 每个 Skill 完成后暂停，展示 diff + 分数变化，等用户确认
```

### 棘轮机制（Ratchet）

```
分数只能上升。每一轮要么改进 Skill，要么干净地回滚。
不会随时间积累局部退化。

示例:
- 轮次 1: 78 分（当前最优）
- 轮次 2: 75 分 < 78 分 → 自动回滚
- 轮次 3: 82 分 > 78 分 → 保留，新最优 = 82
- 轮次 4: 80 分 < 82 分 → 自动回滚
```

## 🎯 对 OpenClaw 的启发

### 1. 技能质量评估体系

**当前 OpenClaw**:
- ✅ 有 `.learnings/` 记录错误和更正
- ✅ 有 `agent-evaluator` 技能（6 维度评估）
- ❌ 缺少系统性的技能优化流程

**可借鉴**:
- 8 维评分体系（结构 60 分 + 效果 40 分）
- 独立子 agent 评分（避免自己评自己）
- 实测表现权重最高（25 分）

### 2. 棘轮机制（Ratchet）

**核心价值**:
- 分数只升不降
- 每轮要么改进，要么干净回滚
- 不积累局部退化

**OpenClaw 应用**:
```
~/.openclaw/skills/ai-news-aggregator/
  ↓
评估（当前得分：72/100）
  ↓
改进（针对最低维度）
  ↓
测试（跑新闻抓取任务）
  ↓
新分 75 > 72 → 保留
新分 68 < 72 → git revert
```

### 3. 人在回路设计

**达尔文.skill**: 每个 Skill 优化完后暂停，用户确认再继续

**OpenClaw 现状**: 
- ✅ 技能修改需要人类确认（已实现）
- ✅ Hook 系统显式注入（已实现）

**可增强**:
- 增加评分可视化（展示 8 维得分）
- 增加 diff 对比（改进前后差异）
- 增加测试报告（实测效果）

### 4. 测试用例体系

**达尔文.skill**: `test-prompts.json` 验证改进是否有效

**OpenClaw 应用**:

## ⚠️ 安全风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| **过度优化** | 针对测试用例过拟合 | 多样化测试集，定期更新 |
| **评估偏差** | 子 agent 评分可能不准确 | 人在回路确认，人工复核 |
| **回滚丢失** | 有价值的改进被误回滚 | 保留历史版本，可手动恢复 |
| **人类疲劳** | 频繁确认导致用户跳过 | 批量确认，设置信任阈值 |
