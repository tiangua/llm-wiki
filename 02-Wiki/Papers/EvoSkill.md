# EvoSkill: Automated Skill Discovery

**arXiv**: [2603.02766](https://arxiv.org/abs/2603.02766)  
**提交时间**: 2026-03-03  
**领域**: AI, Multiagent Systems (cs.AI, cs.MA)

---

## 📋 摘要

Coding Agents 作为通用问题解决者，但缺乏特定领域的专业知识。现有技能大多是手工制作的，进化方法只优化低层 artifacts（提示词、代码），与特定模型和任务紧耦合。

**EvoSkill** 提出一个自进化框架，通过迭代失败分析自动发现和精炼技能。

---

## 🎯 核心贡献

### 1. 失败分析驱动的技能发现
```
执行失败 → 分析原因 → 提出新技能/修改现有技能 → 结构化复用
```

### 2. Pareto 前沿选择机制
- 保留验证性能提升的技能
- 底层模型保持冻结
- 技能层独立优化

### 3. 零样本迁移能力
- 在一个任务上进化的技能可以迁移到其他任务
- 无需重新训练或调整

---

## 📊 实验结果

| 基准 | 提升幅度 | 详情 |
|------|---------|------|
| **OfficeQA** | +7.3% | 60.6% → 67.9% (美国财政部数据推理) |
| **SealQA** | +12.1% | 26.6% → 38.7% (噪声检索增强 QA) |
| **零样本迁移** | +5.3% | SealQA 技能 → BrowseComp |

## 🔍 方法论

### 技能形式
- 结构化、可复用的 skill folders
- 包含：工作流定义 + 代码 + 配置

### 进化流程
1. 执行任务并记录失败
2. 分析失败原因
3. 提议新技能或修改现有技能
4. 在验证集上测试
5. Pareto 选择（保留提升的，丢弃下降的）

### 关键设计
- **模型冻结**: 底层 LLM 不变，只优化技能层
- **结构化存储**: 技能是独立文件夹，可版本控制
- **自动精炼**: 迭代改进，无需人工干预

## 💡 对我们的启发

### OpenClaw 应用方向

1. **技能自动发现机制**
   - 当前 OpenClaw Skills 是手工编写的
   - 可以引入失败分析，自动发现需要新技能的场景
   - 示例：用户多次请求类似任务 → 自动提议新技能

2. **技能层与模型层分离**
   - OpenClaw 架构与此一致
   - 可以在不更换模型的情况下提升能力
   - 通过技能进化而非模型升级

3. **执行边界设计**（关键！）
   - 参考 [[OpenKedge]] 论文
   - 技能进化需要在安全边界内进行
   - 防止 agentic mutation 失控

## ⚠️ 安全风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| **隐性行为模式** | 技能可能携带未预期的行为 | 需要验证和审计 |
| **技能迁移偏差** | 迁移到新任务可能失效 | 需要边界测试 |
| **进化失控** | 自主进化可能偏离意图 | 需要人类确认（OpenClaw 已实现） |

## 🔄 后续进展：被 WikiSkill 超越

2026-08-27 的 [[WikiSkill]] 在同类基准上把 EvoSkill 列为基线并全面超越。两者共享「失败分析 → 提案 → 验证 → 保留提升项」的骨架，差别只在**是否单独维护一层持久知识**：

| 方法 | Gemini-3.5-Flash 五基准平均 |
|---|---|
| No skill | 49.5 |
| **EvoSkill** | 56.1 |
| **WikiSkill** | **68.1** |

EvoSkill 的历代提案历史也会累积，但它没有把「失败模式与成功策略」编译成可检索的结构化知识层，因此下一轮 Proposer 仍在从零开始猜。详见 [[执行层与知识层分离]]。
