# 自进化技能 (Self-Evolving Skills)

**定义**: AI Agent 能够自主发现、创建和改进技能，无需人类手工编写。

---

## 📋 核心概念

### 什么是技能 (Skills)
- **工具 (Tool)**: 单一、自包含的函数
- **技能 (Skill)**: 结构化 bundle，包含多个相互依赖的文件（工作流 + 代码 + 配置）

### 为什么需要自进化
1. **手工编写成本高** — 每个技能需要人类专家设计
2. **人机认知不对齐** — 人类设计的技能可能不是最优
3. **领域专业知识缺乏** — Agent 作为通用问题解决者，缺乏特定领域能力

### 自进化的目标
- 通过迭代改进自动发现新技能
- 在特定任务上超越手工编写的技能
- 保持技能的可读性和可审计性

---

## 🏗️ 实现方案对比

### 方案 1: EvoSkill（失败分析驱动）

**核心流程**:
```
执行失败 → 分析原因 → 提议新技能 → Pareto 选择 → 结构化存储
```

**特点**:
- ✅ 需要真实测试数据
- ✅ 底层模型冻结
- ✅ 技能层独立优化
- ✅ 零样本迁移能力

**实验结果**:
- OfficeQA: +7.3% (60.6% → 67.9%)
- SealQA: +12.1% (26.6% → 38.7%)
- 零样本迁移：+5.3%

**论文**: [[EvoSkill]] (arXiv:2603.02766)

---

### 方案 2: EvoSkills（协同进化验证）

**核心流程**:
```
┌─────────────────┐    反馈    ┌─────────────────┐
│ Skill Generator │ ←───────── │ Surrogate       │
│ (迭代精炼)       │            │ Verifier        │
└─────────────────┘            │ (无需真实数据)   │
                               └─────────────────┘
```

**特点**:
- ✅ 无需真实测试数据
- ✅ Verifier 自主生成标准
- ✅ 多文件技能包
- ✅ 跨 LLM 泛化

**实验结果**:
- SkillsBench: 5 个基线中最高通过率
- 泛化到 6 个额外 LLMs

**论文**: [[EvoSkills]] (arXiv:2604.01687)

## 🔍 关键设计决策

### 1. 技能形式
| 方案 | 形式 | 优点 | 缺点 |
|------|------|------|------|
| EvoSkill | skill folders | 结构化、可版本控制 | 需要文件系统支持 |
| EvoSkills | 多文件包 | 复杂工作流封装 | 审计难度高 |
| OpenClaw | SKILL.md + scripts/ | 人类可读、透明 | 需要手工编写 |

### 2. 验证方式
| 方案 | 验证方式 | 优点 | 风险 |
|------|---------|------|------|
| EvoSkill | 真实测试数据 | 可靠、可量化 | 需要标注数据 |
| EvoSkills | Surrogate Verifier | 无需标注数据 | 验证偏差风险 |

### 3. 进化边界
- **模型冻结**: 只优化技能层，不改变底层 LLM
- **人类确认**: OpenClaw 要求技能修改需人类批准
- **执行边界**: 参考 [[OpenKedge]] 设计

## ⚠️ 安全风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| **隐性行为模式** | 技能可能携带未预期行为 | 需要验证和审计 |
| **验证偏差** | Verifier 可能偏离人类意图 | 需要人类监督 |
| **进化失控** | 自主进化可能偏离目标 | 需要边界控制 |
| **人类无法审计** | 复杂技能难以理解 | 需要文档规范 |

## 💡 OpenClaw 应用方向

### 短期（可实施）
1. **失败分析机制**
   - 记录 `.learnings/ERRORS.md`
   - 定期分析失败模式
   - 提议新技能需求

2. **技能需求发现**
   - 检测重复请求模式
   - 自动提议创建新技能
   - 人类确认后实施

### 中期（探索）
3. **技能自动精炼**
   - 基于使用反馈改进技能
   - A/B 测试不同版本
   - Pareto 选择最优

### 长期（研究）
4. **协同进化验证**
   - 设计内部验证机制
   - 探索无需真实数据的评估
   - 保持人类可审计性
