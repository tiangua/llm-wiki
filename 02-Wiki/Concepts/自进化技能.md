# 自进化技能 (Self-Evolving Skills)

**定义**: AI Agent 能够自主发现、创建和改进技能，无需人类手工编写。

---

## 📋 核心概念

### 什么是技能 (Skills)
- **工具 (Tool)**: 单一、自包含的函数
- **技能 (Skill)**: 结构化 bundle，包含多个相互依赖的文件（工作流 + 代码 + 配置）

### 为什么需要自进化
1. **手工编写成本高** — 每个技能需要人类专家设计
2. **人机认知不对齐** — 人类设计的技能可能不是最优
3. **领域专业知识缺乏** — Agent 作为通用问题解决者，缺乏特定领域能力

### 自进化的目标
- 通过迭代改进自动发现新技能
- 在特定任务上超越手工编写的技能
- 保持技能的可读性和可审计性

## 🏗️ 实现方案对比

### 方案 1: EvoSkill（失败分析驱动）

**核心流程**:
```
执行失败 → 分析原因 → 提议新技能 → Pareto 选择 → 结构化存储
```

**特点**:
- ✅ 需要真实测试数据
- ✅ 底层模型冻结
- ✅ 技能层独立优化
- ✅ 零样本迁移能力

**实验结果**:
- OfficeQA: +7.3% (60.6% → 67.9%)
- SealQA: +12.1% (26.6% → 38.7%)
- 零样本迁移：+5.3%

**论文**: [[EvoSkill]] (arXiv:2603.02766)

---

### 方案 2: EvoSkills（协同进化验证）

**核心流程**:
```
┌─────────────────┐    反馈    ┌─────────────────┐
│ Skill Generator │ ←───────── │ Surrogate       │
│ (迭代精炼)       │            │ Verifier        │
└─────────────────┘            │ (无需真实数据)   │
                               └─────────────────┘
```

**特点**:
- ✅ 无需真实测试数据
- ✅ Verifier 自主生成标准
- ✅ 多文件技能包
- ✅ 跨 LLM 泛化

**实验结果**:
- SkillsBench: 5 个基线中最高通过率
- 泛化到 6 个额外 LLMs

**论文**: [[EvoSkills]] (arXiv:2604.01687)

---

### 方案 3: WikiSkill（持久知识层驱动）

**核心流程**:
```
raw 轨迹 → wiki（永不回滚）→ 每轮只改一个技能 → 验证集门控 → 拒绝则技能回滚、wiki 记账
```

**与前两种的关键差别**：EvoSkill / EvoSkills 的教训都散落在各自的优化历史里，**下一轮演化仍在从零开始猜**。WikiSkill 把「学到了什么」当作一层独立的、持续演化的知识表征来单独维护。

**特点**:
- ✅ **失败不清零** — 被拒提案的 diff、验证分数、结论永久记入 `skill-impact.md`
- ✅ **技能层可回滚，wiki 层永不回滚** — 见 [[执行层与知识层分离]]
- ✅ 训练时**禁止**执行 agent 访问 wiki（否则 63.7% → 60.9%）
- ⚠️ 依赖真实验证集；wiki 无自动剪枝，长跑会膨胀

**实验结果**（五基准平均）:
- Gemini-3.5-Flash：49.5% → **68.1%**
- Qwen-3.6-27B：39.4% → **63.3%**
- 关键消融：去掉 wiki 仅 48.7%，加上后 63.7%（**+15.0**）
- ⚠️ 反例：Qwen-3.5-4B 在 OfficeQA 上 28.5%，**反低于无技能 30.2%**

**论文**: [[WikiSkill]] (arXiv:2608.27454)

## 🔍 关键设计决策

### 1. 技能形式
| 方案 | 形式 | 优点 | 缺点 |
|------|------|------|------|
| EvoSkill | skill folders | 结构化、可版本控制 | 需要文件系统支持 |
| EvoSkills | 多文件包 | 复杂工作流封装 | 审计难度高 |
| OpenClaw | SKILL.md + scripts/ | 人类可读、透明 | 需要手工编写 |
| WikiSkill | SKILL.md + PURPOSE.md（挂 wiki） | 与 wiki 条目双向追溯，失败可溯源 | wiki 无剪枝会膨胀 |

### 2. 验证方式
| 方案 | 验证方式 | 优点 | 风险 |
|------|---------|------|------|
| EvoSkill | 真实测试数据 | 可靠、可量化 | 需要标注数据 |
| EvoSkills | Surrogate Verifier | 无需标注数据 | 验证偏差风险 |
| WikiSkill | 真实验证集 + 门控回滚 + wiki 记账 | 可靠可量化，且失败经验永久留痕 | 需标注数据；门控过严会排除「中性」提案 |

### 3. 进化边界
- **模型冻结**: 只优化技能层，不改变底层 LLM
- **人类确认**: OpenClaw 要求技能修改需人类批准
- **执行边界**: 参考 [[OpenKedge]] 设计

---

## ⚠️ 安全风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| **隐性行为模式** | 技能可能携带未预期行为 | 需要验证和审计 |
| **验证偏差** | Verifier 可能偏离人类意图 | 需要人类监督 |
| **进化失控** | 自主进化可能偏离目标 | 需要边界控制 |
| **人类无法审计** | 复杂技能难以理解 | 需要文档规范 |

## 💡 OpenClaw 应用方向

### 短期（可实施）
1. **失败分析机制**
   - 记录 `.learnings/ERRORS.md`
   - 定期分析失败模式
   - 提议新技能需求

2. **技能需求发现**
   - 检测重复请求模式
   - 自动提议创建新技能
   - 人类确认后实施

### 中期（探索）
3. **技能自动精炼**
   - 基于使用反馈改进技能
   - A/B 测试不同版本
   - Pareto 选择最优

### 长期（研究）
4. **协同进化验证**
   - 设计内部验证机制
   - 探索无需真实数据的评估
   - 保持人类可审计性
